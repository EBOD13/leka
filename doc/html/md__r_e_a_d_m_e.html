leka

Leka is a C++20 limit order book and matching engine built around explicit price-time priority, pooled order storage, intrusive price-level queues, and event-first command dispatch.

Order events

The matching engine dispatches OrderEvent by event_type before reading the payload. This means an event operation is selected first, and only the fields relevant to that operation are validated and interpreted.

NEW

NEW creates a limit or market order. Its payload contains:

  • OrderId
  • Price
  • Quantity
  • Timestamp
  • OrderSide
  • OrderType

Limit orders may execute immediately and rest with any remaining quantity. Market orders execute against available opposing liquidity and never rest.

CANCEL

CANCEL contains only the OrderId of an existing resting order. It does not interpret or require side, type, price, or quantity fields. The order is removed from its price-level FIFO, index, and pooled storage.

MODIFY

MODIFY contains:

  • OrderId
  • newPrice
  • newQuantity

Modification applies to an existing resting limit order. The matching engine compares the requested values with the current order before deciding whether the order can stay in place or must be requeued.

Leka V1 priority semantics

Leka V1 uses Nasdaq-style price/time modification semantics for ordinary displayed limit orders.

Modification Queue position Result
Decrease quantity at the same price Preserved The order is updated in place and the price-level aggregate is reduced.
Increase quantity Reset The order is removed and reinserted at the tail with a new sequence number.
Change price Reset The order moves to the new price level and receives a new sequence number.
Change price and quantity Reset The order is reinserted using the new price and quantity.
No effective change Preserved The event is treated as a no-op.

If an order has partially executed, newQuantity applies to its current remaining quantity. Its original submitted quantity remains available for order history unless a priority-reset modification recreates the resting order with the requested quantity.

Architecture

MatchingEngine decides whether an event is a new order, cancellation, or modification. OrderBook owns resting order state and keeps the OrderIndex, PriceLevel FIFO queues, and OrderPool synchronized. SequenceNumber identifies deterministic processing order and is regenerated only when a modification loses price/time priority.

The event-oriented entry points are:

engine.processEvent(OrderEvent{NewOrder{...}});
engine.processEvent(OrderEvent{CancelOrder{orderId}});
engine.processEvent(OrderEvent{ModifyOrder{orderId, newPrice, newQuantity}});

processOrder(const OrderEvent&) is also available as an alias for callers using the existing order-processing name. Both event entry points return executions for NEW; CANCEL and MODIFY return an empty execution list.

cmake --build build
